# Qué es Thalyx en la revisión estudiada

## Alcance y procedencia

Repositorio: [CesarManzoCode/thalyx](https://github.com/CesarManzoCode/thalyx/tree/0492f72e487e2463b0d7b938365a8b3383364cb9). Revisión: `0492f72e487e2463b0d7b938365a8b3383364cb9`. Consulta: 2026-09-08. Se examinó el árbol completo, el historial y una lectura dirigida del vault, las rutas críticas de implementación y sus pruebas. **No se ejecutaron aquí Thalyx, sus pruebas, BPF, Btrfs ni una máquina física.** Las inferencias siguientes no constituyen una auditoría de seguridad exhaustiva.

El [manifiesto](source-manifest.json) fija las rutas que sostienen esta reconstrucción. Los identificadores E01–E18 permiten distinguir observación e inferencia sin convertir cada contrato en una copia del código.

## Sistema efectivo

Thalyx es un sistema de usuario construido sobre Linux, con un Core que media operaciones, una interfaz humana y una superficie estructurada para agentes. El workspace contiene 31 miembros: 30 crates y el módulo de ejemplo. Usa Rust 2024, declara Rust 1.90 como mínimo y empaqueta SQLite. La imagen fija Linux 6.12.101 y construye el programa base para `x86_64-unknown-linux-musl`. Un programa base como PID 1 no significa que todo el sistema ejecute dentro de un único proceso: hay módulos, motor de inferencia y herramientas confinadas.

La superficie de trabajo actual incluye `contexto`, `hacer` y `evidencia`. `hacer` puede ejecutar un programa JavaScript acotado en QuickJS, encadenar operaciones, validar, conservar un resultado o abandonar un intento. Un proveedor semántico utiliza herramientas Rust reales. Por tanto, las primeras notas del proyecto no bastan para describir su capacidad actual.

## Qué salió bien

La mediación estructurada permite que una operación no sea simplemente una orden de shell. La identidad de versión ata permisos a lo que se activa. Las respuestas parciales y `NOT PROVEN` evitan inventar conocimiento. La apertura relativa a descriptores reduce carreras de paths. La separación entre evidencia y workspace evita perder todo el registro al abandonar un intento. Mantener un motor residente reconoce el coste real de cargar pesos.

Estas son propiedades útiles que deben preservarse aunque cambien sus mecanismos. No se exige conservar un PID 1 monolítico, SQLite para todo, CBOR dentro del kernel o Btrfs como ontología del estado.

## Límites de las afirmaciones

Las pruebas escritas revelan contratos y regresiones buscadas, pero no se consideran pruebas ejecutadas de HEAD. Los informes históricos de máquina conservan su contexto y sus pendientes. No se reporta aquí un total de tests verdes.

La atribución de fragmentos de transcripción muestra coincidencias de origen observadas; no demuestra intención causal del modelo ni inmunidad general a prompt injection. La memoria textual y los índices de Thalyx son servicios de conocimiento, no una razón para introducir embeddings o inferencia en ring 0.

La carga del nuevo kernel queda así delimitada: proporcionar autoridad, vida, aislamiento y recursos comprobables para que Thalyx pueda sostener su semántica con menos inferencias accidentales.
